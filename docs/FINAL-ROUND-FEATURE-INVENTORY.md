# Final Round AI desktop — feature inventory

This is a concise, static-analysis inventory of a shipped desktop artifact, with a read-only mapping to relevant SocketStream code. It describes observed implementation; it is not a recommendation to reproduce anti-capture behavior or use an assistant where it is not permitted.

## Artifact and evidence

- **Target:** `final-round-desktop` **v3.0.7**, Electron + React + TypeScript, from an extracted DMG tree.
- **Artifact SHA-256:** `95924c1e99543f333c2f8a30d31839e0a71cda1cc8a016d021ece4492eb1621c`.
- **Evidence source:** REA report at `/private/var/folders/b0/dj81nc_j2yq2bkmg0yd2sgyc0000gn/T/fr-analysis/FEATURE-INVENTORY.md`; parent evidence `ev_78e2dc3b8e9b4e3c929d835520f5424947c5fe546909428ddb844e8a296de8f8` (`analyze_javascript_application`). Native add-ons were separately inspected with `inspect_macho`.
- **Method:** static analysis only; the app was not installed, run, or connected to vendor services. No prompt-injection-style instructions were found in the analyzed strings.
- **Coverage:** the REA semantic graph covered only `out/main/index.mjs` and seven preloads (8 sources). Its summary reported 66 IPC operations, 14 context-bridge APIs, and one browser window; the preload allow-list enumerates 215 channels (64 queries, 103 commands, 48 events), and static reading identified seven window kinds. Renderer bundles were read directly as text, not analyzed as a complete semantic graph. The report records partial coverage, a 20,000-node per-file cap, 5,124 unselected files, and 79,241 semantic unknowns. Thus “not found” below means not found in the examined artifact/scope, not proof about every unexamined path.

No equivalent for Final Round’s Clerk account system, billing, goals/memory, document library, playbooks, or session-report product was identified in the searched SocketStream modules/docs; this is not an exhaustive absence proof. |

## Unavailable, uncertain, and non-goals

- **Not found in the examined Final Round artifact:** accessibility-tree extraction, local OCR, a system-tray/menu-bar item, or process-name/bundle-ID masking. The app sets its real product name. Its screen understanding is screenshot-based. The REA report also found no identifiable STT/LLM vendor in the main bundle.
- **Content protection is not a universal invisibility guarantee.** The artifact statically calls Electron `setContentProtection`, re-applies it on a 500 ms loop, temporarily enables it for its own screenshot capture, and hides the macOS Dock while its “stealth” setting is enabled. A source comment says Windows maps this to `SetWindowDisplayAffinity`. Static inspection cannot establish that protection works on a given OS/build or against every capture method; it does **not** mask the process identity. In particular, `setContentProtection` is a macOS/Windows Electron API and proves nothing about Linux; GNOME 50/mutter 18 has no equivalent.
- **Linux comparison:** no tested Final Round Linux build or Linux capture-exclusion path was found. The native compositor rules SocketStream writes are documented by those compositors but remain runtime-unverified here; "configured" is reported separately from "verified".
- **Other analysis limits:** server-side behavior is unknown; renderer bundle structure/API use is only partially enumerated; native add-on APIs are inferred from call sites because module symbols are stripped; `silero_vad.onnx` was absent from the extracted tree (version/quantization unresolved); 59 dynamic IPC operations remain unresolved; and runtime behavior—including CGEventTap registration and content-protection enforcement—was not tested.
- **SocketStream safety boundary:** keep capture permission explicit and platform limitations visible. Do not represent content protection or auto-hide as guaranteed, mask process identity, bypass OS permissions/security controls, or hide capture from the user. This inventory makes no exam-evasion recommendations; exam/proctoring evasion is not a product goal.
